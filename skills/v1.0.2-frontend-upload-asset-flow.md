# 视频转素材平台 — 前端上传流程与素材库重构

## 一、项目背景

当前正在开发「AI 视频转素材平台」。

前端技术栈：

- React
- TypeScript
- Vite
- shadcn/ui
- Tailwind CSS
- React Router（如现有项目使用）
- TanStack Query（如现有项目使用）

项目已经具有上传视频、项目选择、剧集切换、素材库、分镜展示、人物提取结果等功能。

**本轮目标：将原先在素材库中手动触发提取任务的流程，改为上传视频时配置自动提取，素材库专注于展示和管理结果。**

请直接检查当前前端仓库并修改已有代码，不要重新创建前端工程。

## 二、现有问题

目前素材库存在：

1. 分镜和人物两个 Tab。
2. 原视频播放器。
3. 人物提取任务触发按钮。
4. 任务执行状态和日志。
5. 人物检测图片列表。

存在以下问题：

- 上传和素材提取是两个割裂的操作。
- 用户上传后还需要进入素材库手动提取。
- 素材库重复展示原视频。
- 素材库承担了任务执行和结果展示两种职责。
- 素材分类不完整。
- 用户无法直观判断每一类素材是否已经生成。

需要重新划分页面职责。

## 三、目标业务流程

```text
创建项目
    ↓
选择剧集 / 上传视频
    ↓
配置是否自动提取
    ↓
选择提取类型
    ↓
确认上传
    ↓
上传成功
    ↓
自动创建 AI 提取任务
    ↓
进入任务中心查看进度
    ↓
任务完成
    ↓
素材库查看结果
```

注意：

- 上传成功不等于提取成功。
- AI 任务必须异步执行。
- 前端不能等待整个 AI 提取完成后才返回。
- 用户离开任务中心后，任务仍然继续。
- 刷新页面后应能恢复任务状态。

## 四、上传页面改造

保留现有上传 UI 风格，新增「自动提取素材」配置区域。

### 4.1 自动提取开关

增加：

**上传完成后自动提取素材**

默认开启。

关闭时：

- 只上传视频。
- 不自动创建 AI 任务。
- 视频仍然保存在项目剧集中。
- 后续可在任务中心手动发起提取。

开启时：

- 显示素材类型选择区域。
- 默认选择所有当前后端支持的提取能力。
- 不支持的能力应禁用并显示「即将支持」。

### 4.2 素材类型

统一使用以下类型：

| 类型 | 标识 | 描述 |
|---|---|---|
| 分镜 | SHOT | 镜头切分、关键帧 |
| 人物 | CHARACTER | 人物检测、人物素材 |
| 对话 | DIALOGUE | 台词、说话人、时间戳 |
| 背景 | BACKGROUND | 场景背景、人物移除 |
| 音频 | AUDIO | 人物语音、音乐、音效 |
| 剧情 | STORY | 剧情事件、人物动作 |

要求：

- 使用 Checkbox 或多选卡片。
- 支持全选、取消全选。
- 至少选择一种类型才能自动提取。
- 不允许选择后端尚未支持的能力。
- 不要把未实现的能力伪装成已支持。

### 4.3 上传提交

用户点击「确认上传」后：

1. 校验项目和剧集。
2. 校验视频文件。
3. 显示真实上传进度。
4. 上传视频到后端。
5. 上传成功后提交提取配置。
6. 如果开启自动提取，后端自动创建任务。
7. 返回任务 ID。
8. 引导用户进入任务中心。

必须防止重复提交。

不要因为前端重复点击而创建多个相同任务。

### 4.4 上传状态

至少包含：

- 待上传
- 上传中
- 上传成功
- 上传失败
- 创建任务中
- 任务创建成功
- 任务创建失败

上传失败应允许重新上传。

上传成功但任务创建失败时，不应删除已经上传的视频，应允许重试创建任务。

## 五、新增任务中心

新增独立的「任务中心」页面。

任务中心用于管理 AI 提取任务，不再将任务操作放在素材库中。

### 5.1 任务列表

每条任务展示：

- 任务 ID
- 项目名称
- 剧集
- 提取类型
- 创建时间
- 开始时间
- 完成时间
- 当前状态
- 处理进度
- 失败原因

### 5.2 任务状态

统一使用：

```typescript
type TaskStatus =
  | "PENDING"
  | "RUNNING"
  | "SUCCESS"
  | "PARTIAL_SUCCESS"
  | "FAILED"
  | "CANCELLED";
```

任务状态必须以后端返回为准。

### 5.3 任务进度

任务中心展示各类素材的独立进度，例如：

```text
第 2 集 · AI 素材提取

分镜       已完成
人物       运行中  65%
对话       待执行
背景       暂不支持
音频       暂不支持
剧情       暂不支持
```

不允许用虚假的定时器模拟 AI 处理进度。

如果后端没有提供百分比，应展示阶段状态，不要自行计算不准确的进度。

### 5.4 实时更新

优先复用现有 SSE 或 WebSocket 机制。

如果当前没有实时事件接口，先使用 TanStack Query 轮询任务状态。

要求：

- 任务运行时自动刷新。
- 任务结束后停止轮询。
- 页面刷新后恢复。
- 网络异常显示重试入口。
- 避免高频无意义请求。

### 5.5 任务操作

支持：

- 查看任务详情
- 查看失败原因
- 重试失败任务
- 补充提取未执行的素材类型
- 查看已生成素材

不要求本轮实现取消运行中任务，除非后端已经支持。

## 六、素材库页面重构

素材库只负责：

**展示、查看、筛选、编辑和导出素材。**

### 6.1 移除内容

从素材库主页面移除：

- 原视频播放器
- 手动启动人物提取按钮
- 手动启动分镜提取按钮
- 任务执行控制区
- 冗长的任务日志
- 重复的任务进度面板

原视频仍保留在视频管理或剧集详情页面，不能删除视频数据。

### 6.2 保留内容

保留：

- 项目选择器
- 剧集切换
- 分镜素材展示
- 人物素材展示
- 图片预览
- 已有的素材详情功能

### 6.3 扩展六个 Tab

```text
素材库
├── 分镜
├── 人物
├── 对话
├── 背景
├── 音频
└── 剧情
```

每个 Tab 必须具有：

- Loading 状态
- 空数据状态
- 失败状态
- 素材数量
- 分页或按需加载
- 对应的素材展示组件

不能将所有素材放在一个巨大的组件中。

### 6.4 分镜 Tab

展示：

- 分镜编号
- 关键帧
- 开始时间
- 结束时间
- 对应视频时间位置
- 关联人物数量

保留现有分镜功能，不破坏已有接口。

### 6.5 人物 Tab

展示：

- 人物素材图片
- 所属剧集
- 来源分镜
- 出现时间
- 人物名称（如已识别）
- 角色归组 ID（如已有）

注意：

**检测到 90 张人物素材，不代表识别到 90 个不同角色。**

如果后端已经提供角色归组结果，优先按角色展示。

如果尚未实现归组，展示检测素材，并明确标识「待归组」。

### 6.6 对话 Tab

展示：

- 说话人
- 对话内容
- 开始时间
- 结束时间
- 对应分镜
- 关联语音文件（如存在）

支持按说话人筛选。

说话人未确定时显示「未知角色」，不能自行猜测。

### 6.7 背景 Tab

展示：

- 背景图片
- 场景名称
- 来源分镜
- 出现时间
- 是否已去除人物
- 背景提取状态

原始分镜截图不能直接标记为「无人物背景」。

### 6.8 音频 Tab

展示：

- 音频名称
- 音频类型
- 时长
- 时间范围
- 试听控件
- 下载入口

音频类型：

- VOICE
- BGM
- SFX
- AMBIENCE

### 6.9 剧情 Tab

展示：

- 剧情事件
- 时间范围
- 参与人物
- 场景
- 情绪
- 人物动作
- 对应分镜

暂时不开发游戏剧情编辑器。

## 七、统一 API 契约

以下是前后端共同遵守的目标接口。

实际实现前，请先检查现有接口文档，尽量兼容已有 API。

```text
GET  /api/media/extraction-capabilities

POST /api/media/videos/upload

POST /api/ai/tasks

GET  /api/ai/tasks
GET  /api/ai/tasks/{taskId}
GET  /api/ai/tasks/{taskId}/steps

POST /api/ai/tasks/{taskId}/retry

GET  /api/media/episodes/{episodeId}/assets
GET  /api/media/episodes/{episodeId}/summary
```

上传请求采用 `multipart/form-data`。

包含：

```text
file
projectId
episodeNumber
autoExtract
extractTypes
```

其中 `extractTypes` 为提取类型数组。

上传成功返回：

```json
{
  "videoId": 1001,
  "episodeId": 2001,
  "autoExtract": true,
  "taskId": 3001,
  "taskStatus": "PENDING"
}
```

上述 JSON 为业务数据示例，实际接口需要遵循后端已有的统一 Result 响应包装。

如果自动任务创建失败，应返回可识别的部分成功结果，保留 videoId、episodeId，并明确错误信息。

### 能力查询

前端通过以下接口获取可用提取能力：

```text
GET /api/media/extraction-capabilities
```

示例：

```json
[
  {
    "type": "SHOT",
    "supported": true
  },
  {
    "type": "CHARACTER",
    "supported": true
  },
  {
    "type": "DIALOGUE",
    "supported": false
  },
  {
    "type": "BACKGROUND",
    "supported": false
  },
  {
    "type": "AUDIO",
    "supported": false
  },
  {
    "type": "STORY",
    "supported": false
  }
]
```

真实支持状态由后端返回，前端不得硬编码为全部支持。

## 八、UI/UX 规范

保持现有深色科技感风格：

- 深蓝色背景
- 紫色主按钮
- 圆角卡片
- 统一间距
- 清晰的状态反馈
- 适配桌面端
- 兼容移动端基本布局

优先复用现有 shadcn/ui 组件。

不要重新设计整个网站。

任务中心应突出进度与状态。

素材库应突出素材内容，而不是任务执行日志。

## 九、代码规范

1. 使用 TypeScript 严格类型。
2. 不滥用 `any`。
3. API 请求统一封装。
4. 业务类型统一定义。
5. 不在组件中硬编码 API 地址。
6. 不在组件中直接处理复杂业务逻辑。
7. 不生成重复组件。
8. 不破坏已有登录鉴权。
9. 不删除现有有效功能。
10. 不使用模拟数据冒充真实后端结果。
11. 遵守项目现有 ESLint、Prettier 规范。
12. 必须处理异步请求的 Loading、Error、Empty 状态。

## 十、验收要求

完成后：

1. 上传页可选择是否自动提取。
2. 提取类型根据后端能力动态展示。
3. 上传成功后能获取任务 ID。
4. 任务中心可以查看真实任务状态。
5. 素材库不再展示原视频播放器。
6. 素材库具有六个 Tab。
7. 已有分镜和人物展示功能保持正常。
8. 不支持的素材类型显示正确空状态。
9. 项目和剧集切换正常。
10. 页面刷新后任务状态可以恢复。
11. TypeScript 类型检查通过。
12. 项目构建通过。

如果 Java 后端接口尚未完成，可以先实现类型和 API 适配层，但不得将模拟数据当作真实结果。
