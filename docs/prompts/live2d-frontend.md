你负责「视频转素材」项目现有的 React + TypeScript 前端。参照最新版「图片转 Live2D 模型工作台」设计稿，实现在浏览器里选图、提交生成任务、查看状态并预览真实 Live2D 模型的流程。先阅读仓库的 AGENTS.md、前端规范和 Java 联调文档，复用现有路由、请求封装、项目选择器和 UI 组件。

一、页面与交互

1. 左侧新增一级导航「Live2D 工作台」，与「素材库」同级。工作台按项目管理，默认进入「图片转 Live2D」。
2. 按设计稿实现三栏布局：
   - 左栏「角色参考图」：支持本地上传和从当前项目的人物素材中选择，展示选中的图片。
   - 中栏「模型预览」：等待生成时展示空状态，生成成功后用 Live2D 网页运行时在画布里渲染实际模型。模型加载后按它实际具备的参数提供眨眼、张嘴、轻微转头等测试按钮。
   - 右栏「生成设置」：填写模型名称、提交「生成 Live2D 模型」，显示任务状态和失败原因。导入已有模型或加载示例可以用于独立验证播放器。
3. 保留设计中的「动作生成」入口，标明将在后续接入。本轮的动作验收通过模型参数测试按钮完成。

二、接口与状态

1. 本地图片先走现有上传接口取得 uploadFileId。从人物素材选择时使用 sourceAssetId。提交 modelName 和其中一个来源 ID。
2. 按 Java 联调文档提交与轮询任务。使用 taskId、status 和可选 stage。状态为 QUEUED、RUNNING、SUCCEEDED、FAILED。
3. 成功时读取 result.modelId 和 result.modelEntryUrl。把 .model3.json 传给网页运行时，并验证相对路径引用的模型、贴图等都能加载。以真实接口鉴权方式为准。
4. 区分任务生成失败与模型预览加载失败。生成期间避免重复提交，任务结束停止轮询。切换项目或离开页面时清理旧轮询和播放器资源，避免旧任务结果覆盖当前项目。

三、验收与交付

- 先用 Haru 或仓库现有示例验证播放器。示例明确标注为「示例模型」。
- 和 Java、Python 联调一张真实角色图，完成「选图 → 提交 → 查询 → 加载生成模型 → 点击动作按钮」。
- 缺少后端环境时，明确记录已经通过的播放器验证和待联调项。
- 将本轮开发提示词原样保留到当前仓库 docs/prompts/live2d-frontend.md，并输出本地启动和人工验收步骤。
