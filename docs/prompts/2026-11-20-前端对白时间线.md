# 前端对白时间线开发提示词

在 `video-asset-web` 完成素材库「对话」Tab。先阅读 `AGENTS.md`、当前对白占位页、分镜时间线、`VideoPlayer` 和任务中心代码。接口以同级 Python 仓库的 `../video-asset-ai/docs/dialogue-extraction-contract.md` 为准。页面从开发开始就接正式 Java 网关接口。契约中的三句对白只用于核对字段、独立测试和边界断言。

## 实现范围

1. 复用原视频播放器、播放时间回调和待定位机制。按真实起止时间在播放器下方显示可点击的对白时间线，下方提供时间排序的台词列表。时间线保留静音空白，重叠对白需要能分别点击和辨认。台词行展示起止时间、说话人和文字。
2. 点击句段或台词时跳转至 `startMs / 1000` 秒。播放时按 `[startMs,endMs)` 高亮当前句，重叠时高亮所有命中的句段。切换剧集时清空选中、待跳转和播放器进度。键盘可操作时间线和台词。
3. 使用 `GET /api/media/episodes/{episodeId}/assets?type=DIALOGUE`，通过现有鉴权和运行时类型校验读取，多页用 `sourceTaskId` 固定版本。展示匿名说话人和「未知说话人」，提供按说话人筛选，筛选后的定位继续使用原视频时间。
4. 沿用现有任务中心和能力发现。支持发起和重试，显示未启用、排队、处理、失败、零对白和成功状态。重新提取期间仍可浏览之前的成功内容。

## 开发与联调安排

本轮先完成代码和本端必要检查，按共用契约实现正式接口。三端各自开发，不等待其他端，不启动整链路联调。交付时汇报文件、现有检查结果、启动配置和后续联调入口。本端独立检查包括下列项目。

- 运行 `pnpm lint` 和 `pnpm build`。在独立测试中覆盖时间线留白、重叠高亮、边界、点击跳转、视频未就绪时的点击、未知说话人、空结果与剧集切换。

## 收到通知后集中验收

等用户确认三端都已完成开发，再执行下列真实联调。三端使用同一集带人声的原视频，测试示例仅用于字段核对和本端独立测试。

- 使用 Java 交接的真实剧集和网关地址验证，先确认能力接口已经启用 `DIALOGUE`。在浏览器发起真实任务、轮询至结束，并从实际素材查询加载时间线。核对句段数量、说话人筛选、点击对白后播放器时间及播放时高亮。交付时给出可复查的剧集和任务 ID、实际请求及跳转验证结果。
- 上游尚未就绪时按实际状态展示加载、未启用、失败或空结果。页面联调路径接真实接口，用户可见数据来自实际响应。临时假接口、硬编码台词和示例回退不属于交付。
- Java 尚未就绪时，交付状态写「待真实联调」，明确阻塞的接口或配置。浏览器完成实际验证后再更新状态。
