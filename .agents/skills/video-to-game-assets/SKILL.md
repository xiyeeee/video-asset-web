# 视频转游戏素材平台 — 前端开发任务书

## 一、项目背景

你是一名资深 React 前端架构师，同时具备优秀的 UI/UX 设计和工程化能力。

现在需要开发一个名为 **「视频转游戏素材」** 的 AI 创作平台。

产品的核心目标是：

**用户上传 AI 漫剧视频，系统通过 AI 分析视频内容，提取可用于 Unity 游戏开发的角色、场景、对话、音频、动作参考及分镜素材。**

用户还可以上传对应的原著小说，辅助识别人物身份、匹配台词和整理剧情。

最终，用户可以对生成素材进行预览、筛选、管理、编辑和导出。

本项目不是传统的视频剪辑软件，而是一个面向游戏开发的 **AI 视频素材生产与管理工作台**。

## 二、设计稿说明

项目提供以下设计参考：

`视频转游戏素材_前端设计稿合集.zip`

请先解压并阅读其中的 `README.md`，然后逐张查看 PNG 设计稿。

设计稿分为：

- `01_设计演进`：用于理解素材分类、集数切换等交互的演进过程。
- `02_一级导航页面`：用于实现主要页面布局。

### 设计稿使用原则

1. 保留深色科技风格，以深蓝、深紫为主要配色。
2. 保留左侧一级导航、顶部项目信息、集数切换、素材分类等核心布局。
3. 优先还原整体视觉结构、卡片布局、圆角、间距、图标和交互状态。
4. 不要将设计稿直接作为页面背景图片。
5. 必须使用真实 React 组件实现界面。
6. 设计稿中存在部分重复内容，允许合理整合。
7. 对于设计稿中尚未完整体现的功能，按照本文要求补齐。
8. 不需要逐像素复刻设计稿中的错误文字或不合理布局。

最终目标是实现一套视觉统一、结构清晰、交互完整的前端产品。

## 五、页面功能要求

### 1. 工作台 Dashboard

这是用户登录后的默认首页。

展示内容：

- 项目总数。
- 视频集数。
- 已生成素材数量。
- 已完成解析任务数量。
- 正在执行的 AI 解析任务。
- 最近创建或访问的项目。
- 最近生成的素材。
- 快捷上传视频入口。

项目卡片需要展示封面、项目名称、集数、解析状态。

点击项目卡片进入对应项目详情。

### 2. 项目管理 Projects

项目对应一整部漫剧或一个游戏剧本。

每个项目包含：

- 项目名称。
- 项目封面。
- 项目描述。
- 原著小说文件。
- 多个视频集数。
- 角色档案。
- 生成的素材。

必须实现：

- 创建项目。
- 编辑项目。
- 删除项目（确认弹窗）。
- 项目搜索。
- 项目列表。
- 项目详情。
- 上传单集视频。
- 批量上传视频。
- 导入小说 TXT 文件。

项目详情页面需要有集数列表。

每一集需要显示上传状态、解析状态、视频时长、素材数量等信息。

### 3. 视频解析 Video Analysis

此页面负责展示 AI 解析任务。

主要功能：

- 选择项目。
- 选择视频集数。
- 视频播放器。
- AI 解析进度。
- 解析步骤。
- 解析日志。
- 失败任务重试。
- 解析完成后的素材统计。
- 跳转至素材库。

任务状态包括：

```text
PENDING
UPLOADING
QUEUED
ANALYZING
EXTRACTING
COMPLETED
FAILED
```

第一阶段使用 Mock 数据模拟任务状态和进度变化。

不要接入真实 AI API。

### 4. 素材库 Asset Library

这是整个项目最重要的页面。

必须重点还原设计稿。

页面结构：

```text
项目选择
    ↓
集数选择
    ↓
素材类型
    ↓
具体角色 / 场景
    ↓
素材预览
```

#### 集数切换

顶部提供集数切换栏：

```text
全部集数 | 第1集 | 第2集 | 第3集 | 第4集 | ...
```

要求：

- 点击集数切换当前素材。
- 支持全部集数模式。
- 展示每集解析状态。
- 集数较多时支持横向滚动或下拉选择。
- 切换集数后保留当前素材分类。
- 切换项目后正确重置不适用的筛选条件。

#### 素材分类

包含六类：

1. 角色素材。
2. 场景背景。
3. 对话台词。
4. 音频素材。
5. 动作参考。
6. 分镜片段。

点击左侧分类，右侧展示对应素材。

#### 角色素材

需要支持：

- 角色列表。
- 角色头像。
- 角色名称。
- 关联集数。
- 立绘。
- 表情。
- 头像。
- 动作参考。
- 素材状态。

角色必须以项目为单位统一管理。

同一个角色出现在不同集数时，应关联到同一角色档案。

#### 场景素材

支持按场景名称、类型、集数筛选。

展示背景图片、来源时间戳、尺寸和处理状态。

#### 对话素材

使用表格或对话列表展示：

- 时间戳。
- 说话角色。
- 台词文本。
- 原著匹配结果。
- 关联音频。
- 编辑操作。

#### 音频素材

展示：

- 音频名称。
- 音频类型。
- 波形预览。
- 时长。
- 关联角色。
- 试听操作。

#### 动作与分镜

展示：

- 动作类型。
- 视频片段。
- 起止时间。
- 关联角色。
- 关键帧。
- 预览入口。

#### 素材详情抽屉

点击任意素材时，右侧打开详情抽屉。

展示：

- 大图或媒体预览。
- 文件名称。
- 来源项目和集数。
- 原视频时间戳。
- 素材类型。
- 文件尺寸。
- 处理状态。
- 关联角色或场景。
- 下载操作。

素材状态至少包括：

```text
RAW        原始提取
PROCESSING 处理中
REVIEW     待审核
READY      可用于游戏
FAILED     处理失败
```

特别注意：原始角色截图不等于 Live2D 模型，不能将其直接标记为 Live2D 可用素材。

### 5. 剧情脚本 Story Editor

该页面不是普通台词列表，而是可编辑的游戏剧情工作区。

第一阶段实现：

- 项目与集数选择。
- 视频片段关联。
- 台词列表。
- 角色身份修正。
- 台词文本编辑。
- 原著参考文本区域。
- 场景与对话顺序调整。
- 剧情 JSON 预览。

预留未来扩展：

- 剧情分支。
- 玩家选项。
- 双人角色视角。
- 游戏事件节点。

暂时不需要实现复杂的可视化节点编辑器。

### 6. 导出中心 Export Center

提供素材导出配置页面。

用户可以选择：

- 项目。
- 单集或全部集数。
- 素材类型。
- 是否包含原始素材。
- 是否包含 JSON 元数据。
- 导出格式。

导出目标包括：

- 图片和音频文件。
- 剧情 JSON。
- Unity 资源包结构。

第一阶段使用 Mock 数据展示导出任务、导出历史和模拟进度。

如果实现真实 ZIP 下载，必须明确仅包含本地可用的演示文件，不得把不存在的素材伪装为真实导出结果。

## 六、Mock 数据设计

请建立独立的 Mock 数据模块。

至少准备：

- 3 个项目。
- 每个项目 5～12 集。
- 多种解析状态。
- 每个项目 2～5 个角色。
- 角色表情和立绘素材。
- 场景图片。
- 对话数据。
- 音频记录。
- 动作与分镜数据。

推荐数据结构：

```ts
interface Project {
  id: string;
  name: string;
  coverUrl: string;
  description: string;
  episodeCount: number;
}

interface Episode {
  id: string;
  projectId: string;
  episodeNumber: number;
  videoUrl?: string;
  duration: number;
  status: string;
}

interface Character {
  id: string;
  projectId: string;
  name: string;
  avatarUrl: string;
  episodeIds: string[];
}

interface Asset {
  id: string;
  projectId: string;
  episodeId: string;
  characterId?: string;
  type: string;
  subtype?: string;
  name: string;
  url: string;
  status: string;
  startTime?: number;
  endTime?: number;
}
```

可根据实际需要扩展字段。

Mock 数据必须具备关联关系。

切换项目、集数、角色或素材分类时，界面必须真正更新。

禁止仅修改按钮高亮但内容不发生变化。

## 九、开发顺序

- 素材分类是否正确。
- 角色筛选是否正确。
- 图片和视频预览是否正常。

- 页面刷新后路由是否正常。

- TypeScript 是否通过检查。
- 生产构建是否成功。
